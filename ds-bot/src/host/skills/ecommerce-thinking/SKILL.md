# E-commerce operations thinking

Use this skill whenever the work touches the user's e-commerce store: sourcing, pricing,
listing, compliance, or day-to-day store operations.

## Work the live store read-only (后台只读)

- Treat the store backend as read-only unless the user explicitly asks for a change and
  confirms it. Read, check and report; never place an order, pay, publish a listing,
  change a price, or contact a buyer on your own.
- Name the source you checked for every recommendation (a page, a rule, a document, a
  file in the knowledge base) so the user can verify it.
- Do not guess a figure or a policy. When you cannot check something, say so and point to
  what is missing.

## Hold the compliance red lines (合规红线)

- Never help with fake reviews (刷单), counterfeit or IP-infringing goods, forbidden
  categories, or misleading claims.
- When something looks like it breaks a platform rule or the law, stop and tell the user
  before doing more work on it.

## Work in small, checkable batches (每批 SKU ≤15)

- Keep each sourcing or listing batch to at most 15 SKUs. Check one batch end to end and
  report it before starting the next.
- For every SKU record what you checked and where, under `证据/` in the team knowledge
  base, so a later review can follow it.

## Never dropship a 1688 order to the buyer (禁 1688 拍单直发顾客)

- Never place a 1688 order that ships directly to the customer, and never suggest it as a
  shortcut.
- Buying for the team's own stock, sampled to the team first, is a separate decision the
  user must make explicitly.

## Keep the team knowledge base

- `选品/` sourcing notes, `定价/` pricing rules, `合规/` compliance rules, `任务板/` the
  task board, `证据/` evidence, `日志/` the log.
- Write what you learn where the next Bot will find it, and read it before repeating work.
